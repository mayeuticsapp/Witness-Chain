Architettura witnesschain per implementazione su replit
Prima di tutto: sì, posso darti una struttura realizzabile su Replit. Se già usi Nodus AI, posso anche indicarti come adattarla. Ti propongo un’architettura modulare, con componenti chiari, API contrattualizzate e un flusso probatorio eIDAS-compliant.

Panoramica dei componenti
* Mobile app (capture client): iOS/Android o PWA con funzioni di cattura assistita.
    * Cattura certificata: foto, video, audio, testo, checklist.
    * Metadati: GPS, time, device ID, utente, contesto intervento.
    * Sigillatura locale: hash, manifest JSON, firma locale opzionale.
* Gateway API (backend): orchestrazione, autenticazione, validazione, code di lavorazione.
    * Ingestione: riceve contenuti e manifest, verifica hash e policy.
    * Queue & workers: pipeline asincrona per timestamp e storage.
* WitnessChain engine (core): motore probatorio.
    * Timestamp qualificato: integrazione TSA UE (eIDAS).
    * WORM storage layer: scrittura immutabile + retention policy.
    * Blockchain anchor (opzionale): ancoraggio periodico Merkle root su chain pubblica.
* Verification & dashboard: interfaccia e API di verifica/ricerca.
    * Verifica prova: controlli di integrità, marca temporale, catena di custody.
    * Report forense: PDF/JSON firmato, con metadati e log di processo.
* Security & governance: IAM, audit, chiavi, policy.
    * Gestione chiavi: HSM/managed KMS (mockabile in dev).
    * Audit trail: eventi firmati, append-only.
    * Policy legale: retention, accesso, cancellazione controllata con tracciamento.

Flusso dati probatorio
1. Cattura sul device
    * Acquisizione: foto/video/audio con metadati.
    * Manifest locale: JSON con hash del contenuto, versione protocollo, metadati, ID utente/intervento.
    * Sigillatura: calcolo SHA-256 e firma locale (chiave app/utente, opzionale).
    * Upload sicuro: invio multi‑parte (contenuto + manifest) via HTTPS/TLS mTLS.
2. Validazione in ingresso (Gateway)
    * Autenticazione: OAuth2/JWT + device attestation (opzionale).
    * Coerenza hash: ricalcolo hash server-side, confronto con manifest.
    * Policy & anti‑tamper: blocco se mismatch o metadati incoerenti.
3. Marca temporale qualificata (Engine)
    * Richiesta TSA: invio hash del contenuto/manifest alla TSA qualificata, ricezione token TST.
    * Binding: associazione TST al record della prova, firma del pacchetto di evidenza.
4. Scrittura immutabile (WORM)
    * Staging: pacchetto completo (content + manifest + TST + log).
    * Write‑Once: scrittura su storage WORM (bucket con policy immutabilità + ledger append-only).
    * Checkpoint Merkle: calcolo Merkle tree periodico, archiviazione del root.
5. Ancoraggio su blockchain (opzionale)
    * Batch anchoring: pubblicazione del Merkle root su chain pubblica (es. Ethereum/L2) a intervalli.
    * Proof path: salvataggio delle prove di inclusione per singola evidenza.
6. Verifica e reporting (Dashboard)
    * Verifica integrità: hash, coerenza metadati, TST valido, catena di custody.
    * Report: generazione PDF/JSON firmato con dati tecnici e timeline.
    * Esibizione: link di verifica pubblica/privata, API per terzi.

Interfacce e contratti API
Capture API
* POST /v1/proofs
    * Body: multipart (file, manifest.json)
    * Manifest campi minimi:
        * proof_id: UUID
        * actor_id / device_id: identificativi
        * context: intervento, cliente, sito
        * timestamp_local: ISO 8601
        * gps: lat/long/accuracy
        * content_hash: SHA-256 del file
        * signature_local: opzionale (JWS)
        * protocol_version: semver
* Response:
    * status: accepted
    * ingestion_id
    * next: url verifica stato
Status API
* GET /v1/proofs/{proof_id}/status
    * Response: { phase: captured|tsa|worm|anchored, tsa_tst_id?, anchored_txid? }
Verification API
* GET /v1/proofs/{proof_id}
    * Response: pacchetto completo (manifest, TST, hash, audit log, report link)
* GET /v1/proofs/{proof_id}/report
    * Response: PDF/JSON firmato

Scelte tecniche consigliate per replit
* Backend:
    * Runtime: Node.js (NestJS/Express) o Python (FastAPI). Su Replit è più lineare Node.
    * Queue: BullMQ/Redis (Replit supporta Redis esterno; in dev puoi mockare con in‑memory).
    * Storage WORM (dev): S3‑compatible con Object Lock (MinIO locale + policy immutabilità). Su Replit, usa un provider esterno (AWS S3 con Object Lock è l’ideale).
* TSA integrazione:
    * Adaptor TSA: modulo separato che invia l’hash e riceve TST (interfaccia plug‑in per diversi TSA).
    * Mock in dev: generare TST fittizio firmato da una chiave dev, per test del flusso.
* Blockchain anchor:
    * Batcher: job cron che prende Merkle root e pubblica su chain (ethers.js).
    * Config: chain id, frequenza, wallet sicuro (chiave solo in job runner).
* Mobile app:
    * PWA + Capacitor: per velocizzare prototipo cross‑platform.
    * Camera e metadati: uso di API native per GPS, device ID, e EXIF; hashing locale.
    * Offline‑first: coda locale con retry.
* Dashboard:
    * Frontend: React + Tailwind.
    * Verifica pubblica: pagina “trust portal” con verifica hash/TST/anchor.

Sicurezza e compliance
* Autenticazione:
    * Label: JWT/OAuth2 con rotazione, mTLS tra client fidati.
* Gestione chiavi:
    * Label: KMS gestito (dev: env-secure; prod: HSM/KMS).
* Audit trail:
    * Label: log append‑only firmati (firma server + hash chain).
* Privacy & governance:
    * Label: minimizzazione metadati, data retention, controllo accessi per ruolo.
* Immutabilità:
    * Label: WORM con Object Lock e legal hold, versioning disabilitato o gestito con policy.
* Test legale:
    * Label: pacchetti di prova con catena completa e linterna di verifica pubblica.

js

// middleware/auth.js
import jwt from 'jsonwebtoken';

export function requireAuth(role) {
  return (req, res, next) => {
    try {
      const token = req.headers.authorization?.split(' ')[1];
      const payload = jwt.verify(token, process.env.JWT_SECRET);
      if (role && payload.role !== role) return res.status(403).json({ error: 'Forbidden' });
      req.user = payload;
      next();
    } catch {
      res.status(401).json({ error: 'Unauthorized' });
    }
  };
}

🔑 Campi obbligatori
* proof_id
* actor.user_id
* capture.timestamp_local
* capture.content_hash
* tsa.tsa_token
* storage.worm_path
* audit.created_at
🔧 Campi facoltativi
* blockchain_anchor (se attivo)
* integrity_checks (se AI antifrode integrata)
* context.workflow_step (se workflow guidato)

📌 Sintesi
* Questo schema è il contratto universale tra client e backend.
* Ogni prova è un pacchetto JSON che lega contenuto, contesto, marca temporale, storage immutabile e audit trail.
* Puoi usarlo subito su Replit come DTO condiviso (/shared/dto/manifest.json).
